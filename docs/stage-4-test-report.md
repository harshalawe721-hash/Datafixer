## Owner decisions and requirements: how each was met and tested

| Decision / requirement | How | Tested by |
|---|---|---|
| 1. Duplicates: keep the first copy | The first row of each group of identical rows is kept. Each removed row records "Exact copy of row N" (original row number) | `fixes.test.ts`, test pack |
| 2. Capitalization: most common spelling; ties asked | Ties are listed as choices. Nothing in a tied group changes until a spelling is chosen | `choice-fixes.test.ts` (tie test), browser test |
| 3. CSV: UTF-8 with BOM | Every CSV download starts with EF BB BF. Checked in the website (V1) and by Python | `csv-export.test.ts`, browser test (real downloaded file) |
| 4. Excel: change only edited cells | The original package is patched. Unchanged parts are copied byte for byte | `xlsx-export.test.ts` (openpyxl + zipfile byte comparison) |
| Preview before any automatic change | Every fix opens a preview. Applying uses exactly that preview and is refused if the data changed since (`stale-preview`) | `fixes.test.ts`, browser test |
| Original file unchanged | The file is only read. SHA-256 before and after are identical | `csv-export.test.ts`, large-file test (all runs) |
| Undo and Redo | History of changes. A new change after Undo ends the redo chain, and those entries stay listed as "Undone" | `edit-session.test.ts`, browser test |
| No silent ambiguous corrections | Ties, ambiguous dates (03/04/2024), two-digit years, decimal-comma numbers, percentages and phone numbers with a different digit count are never changed. They are listed with the reason | `choice-fixes.test.ts`, `fixes.test.ts` |
| No silent loss of Excel features | Excel download keeps everything (verified). CSV and .xls downloads list what can't be kept *before* creating the file and again in the summary | `xlsx-export.test.ts`, browser test |
| Exported files reopened and verified | Website: generated bytes re-read with DataFixer's reader and compared cell by cell before "Export successful" (V1, V2). Tests: Python `csv` (V3) and openpyxl (V4–V6) | `csv-export.test.ts`, `xlsx-export.test.ts` |
| Privacy | All work happens in the browser's worker. The browser test confirms no uploads and no off-site requests during fixing and download | browser test |
| Responsive on phones and tablets | Full-width preview sheets, stacked lists instead of wide tables, buttons at least 40 px high, no sideways page scrolling | browser test at 390 px and 800 px |

## Safeguards

| Safeguard | How | Tested by |
|---|---|---|
| S1 Formula protection | Automatic fixes skip formula cells, and rows/columns containing formulas are never removed (listed as skipped). Editing a formula cell by hand shows the formula and needs an explicit tick. calcChain is removed when a formula is replaced | `fixes.test.ts` (formula test), `edit-session.test.ts`, `xlsx-export.test.ts`, browser test |
| S2 Reference protection | Before rows/columns are removed from an Excel file, the whole workbook is checked: formulas here and on other sheets, merged cells, conditional formatting, data validation (including newer formats), filters, tables, comments, drawings, charts, pivots and named ranges. Dynamic references count as affected. If anything is affected, nothing is removed and “Clear the cells instead” is offered. .xls files never remove rows | `xlsx-export.test.ts` (blocked, clearing, download refusal), browser test (warning names the chart and the Summary formula) |
| S3 Download summary | Shown only after creation **and** verification pass: original and downloaded file names, cells edited, rows/columns removed, duplicates removed, automatic corrections, manual edits, features not kept, warnings, what was verified | `csv-export.test.ts` (exact values), browser test |
| S4 Recoverable large exports | Memory is checked before starting. Cancel, failure or low memory download nothing and keep every change. "Try again" works. No partial file is ever offered | `csv-export.test.ts`, large-file test |
| S5 Change history | Per cell: position, original value, new value, operation, status (Applied/Undone). Removed rows/columns with the reason. Paged, and works with Undo/Redo | `edit-session.test.ts`, browser test |

## Known limitations

- **"Fix all" on very large files is the slowest step** (about 37 s at 150 MB on a desktop), because each fix re-reads the sheet in turn. The page stays responsive and Cancel works.
- **Excel download needs memory to re-read the new workbook for verification.** On low-memory devices, large workbooks may only be downloadable as CSV. The page says so before anything is created.
- **Rows and columns are never removed when anything in the workbook refers to them**, even when Excel itself could update the reference. References are not rewritten (planned as a possible later proposal); clearing is offered instead.
- **.xls files:** rebuilt as .xlsx. Fonts, colours, fills and borders, conditional formatting, data validation, charts and images are not kept, and "very hidden" sheets become hidden (measured, listed to the user). Rows are never removed from .xls files.
- **Cells that can't be written alone:** the first cell of a shared formula, and cells inside multi-cell array formulas or data tables. The Excel download stops with an explanation, and CSV is suggested.
- **Strict Open XML and ZIP64 workbooks** can only be downloaded as CSV.
- **Only one Excel sheet is held at a time** (Stage 2). Switching sheets asks before discarding that sheet's changes.
- **"Export successful"** means the file was created and checked. Saving it to the device is done by the browser.
- Real-device testing covers one Android tablet (see above). Phones, iOS, Safari and Firefox have **not** been tested for Stage 4.
